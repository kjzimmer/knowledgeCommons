Notes on particular sections:

- **Agents and models (8).** As the answers set: curator, facilitator and Holon on Sonnet 5.5; challenger on Opus
  5.5; the auditor's model is a setting per kind of work it checks, never the model that did the work (Opus audits
  Sonnet's work, Sonnet audits Opus's challenges, Haiku available for mechanical checks). Every agent's output is
  JSON validated by code before it is stored. The Agents page states that these are different Claude models, not
  different providers.
- **Audits without full text (8, 11).** The auditor records a provenance result per cited source (verified against
  full text, checked against abstract or metadata only, unverifiable); a point shows, for example, "Audited ·
  provenance: 1 of 3 sources verified", and says when its claims about a source rest on the model's knowledge.
- **Endorsed (11).** Not computed in this slice; endorsements and their stated positions are shown, with a note
  that the level is not yet active.
- **Scout (9).** Plain code against OpenAlex, Crossref, Unpaywall, arXiv, PubMed Central and DOAJ, with a polite
  user agent that names no person, robots rules respected, a daily cap of 25 works; looks for open versions of every
  work before recording "citation only"; Haiku only to rank and summarize.
- **Monitor (4).** Daily and on demand: the app, the database, one cheap call per model in use, the key's expiry
  from `ANTHROPIC_KEY_EXPIRES` (alert under 14 days), whether scheduled jobs ran, spend against each share. Email
  through Resend's HTTP interface (no new package). Results on a public Operations page.
- **Scheduler.** An in-process job runner with its jobs recorded in Postgres, so a restart does not lose a pending
  revision or a check.

## 5. Where question-loop data lives (decision 0007)

As agreed in the answers (B1):

- **Postgres** holds dialog and operational data with full revision history: posts, extractions and corrections,
  endorsements, disclosures, working drafts, events, every reading revision, and the sandbox flag on each record.
- **The repository** holds artifacts' metadata, entries, the map, agent files, requirements and decisions as now,
  plus `questions/<id>/reading.md` for recorded readings. While `RECORD_MODE=sandbox`, only the first audited
  seed readings are committed; in `keep` mode, every recorded revision.
- **R2** holds artifact files the rights allow, and the nightly full export.
- **Full export**: one bundle of everything the commons holds that may be published (Postgres records as plain
  files, readings, artifact files the rights allow), produced nightly and on request.

**This is an interim decision.** The wider question stays open, to come back to later: how all of the commons is
kept (knowledge, R2 files, the database, app code, configuration and everything else the app needs to run) so that
the app runs efficiently, nothing is lost if the app or its host disappears, and anyone can fork the whole commons.
Decision 0007 will say so and link the open question. To keep that question open, the export is built as a
complete, self-describing bundle (records, a manifest of R2 files with checksums, the schema version and the
commit of the code that wrote it) rather than a convenience download.
